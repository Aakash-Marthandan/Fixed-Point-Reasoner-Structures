### 11.1 EqR ⚠ CLOSED — appendix C.1 / D.1 / A.3 + Tables 2, 3, 4, 10, 12, 15, 16, 17 read from the PDF (arXiv 2605.21488)
- **Architecture = TRM's, verbatim** ("we follow the architecture used in the TRM paper, keeping the model components and training procedure identical unless otherwise specified"): Sudoku = L-layers 2, H-cycles 3, L-cycles 6, outer loop 16, hidden 512, **5.03M**, token mixer = MLP-mixer over the sequence (self-attention only on Maze), 42 equivalent layers per outer iteration, NLE 672 at D=16. The public TRM code fixes the rest: SwiGLU (expansion 4, inter = multiple of 256 → 1536; token-mixer inter 512 over 81+16 tokens), **post-norm** RMSNorm (parameter-free, eps 1e-5) after every sub-block (the review's "pre-norm" was a mis-statement — HRM/TRM code comments read "Post Norm"), no positional encoding for MLP-T, embed scale √512, LeCun trunc-normal init, bias-free lm_head, a zero-init 16-token puzzle-embedding prefix (one identifier on Sudoku), z_H/z_L initial states = fixed trunc-normal(std 1) buffers, gradient only through the LAST H-cycle (6 L passes + 1 H pass of the 21), carry detached between segments. Param arithmetic checks: 2 × (2.36M channel-SwiGLU + 0.15M token-SwiGLU) + I/O ≈ 5.03M.
- **Training regime (Table 17):** Adam-atan2, **constant lr 1e-4** after a 2k linear warmup, weight decay 1.0, EMA 0.999, (β1, β2) = (.9, .95), **global batch 768, 50k steps** (= 38.4M segment-updates), "we report the best checkpoint observed during training" (the HRM/TRM lineage's best-TEST-eval convention — a protocol-column fact for the comparator table). Data (Table 16): 1,000 × (1000+1) = **1,001,000** training examples (HRM's shuffle incl. digit permutation), 422,786 test; Sudoku-Lite = a 2048-case eval subset (EqR 84.3 there vs 86.4 full).
- **Dynamics:** z_{k+1} = z_k + (1−λ) r_θ(z_k; x) + β ε_k per inner iteration, λ = .05, β = .01 (Table 12: β .01 → 86.4, .05 → 85.9, .1 → 86.3, learned ε → 87.1). **RI:** z_H ∼ N(0, σ_H I), z_L ∼ N(0, σ_L I), default σ = 1 (TRM 84.06 → TRM+RI 86.03 at 50k; best σ_H = 1, σ_L = 8 → 87.30; learnable z0 = 83.99, worse). **SOT** = "splits the trajectory into segments, supervises the end of each segment, and takes an optimizer step immediately" — the ONLINE loop with a persistent carry across optimizer steps (HRM/TRM's `train_state.carry`), one segment per step, rows replaced when they finish.
- **Construction path (Table 2, D=16, B=1):** feedforward 2.6 → weight-tied 32.6 → +SOT+depth×16 74.7 → +hierarchical recurrence 76.5 → **+ACT training 84.8** (= Table 3's "baseline") → +RI 86.0 → +RI+NI 86.4 → D=64 B=1 93.0 → D=64 B=128 Top-1-residual 99.8. ## §13. PRE-MORTEM AUDIT of the sportC1 build (2026-09-02, run AFTER the harness passed; the rung-2 method: data-validity first, delay second, each item against a harness scenario, a chain guard, a test, or a procedure)

**Catches (fixed before this appendix was written; each now harness- or test-covered):**
- **PM-1 (data-validity): val-selection blind to the hot phase.** `select_ckpt` was run on the stage-B dir only, so a two-stage arm whose monitor peaked in the 50k cosine phase (the pilot's P1 peaked at 20k) would have reported a worse stage-B grid as "val-selected". Fix: selection over BOTH stage dirs on the headline key (ties → the later stage); the chosen grid's path is echoed (`VALBEST <arm> A:|B:…`) and the full/scan/census run on it. Harness S7.
- **PM-2 (data-validity/completeness): the "vsel == final" copy branch banked nothing.** On a 4×4 node the final tarball is assembled by whichever worker completes last from the GCS `evals/*.tgz`; a copied-not-banked `full_final` or `census_final` dir on another worker would have been absent from `sportC1_final.tgz`. Fix: `bank_eval` (tgz + OK marker) in both copy branches. Harness S1/S5.
- **PM-3 (delay): the field cell recompiled once per inference step** because the unused `t_norm` keyed the evaluator's jit cache (16 variants of a 21-pass segment per eval). Fix: `t_norm = 0` for `cell_kind == "trm"` in the evaluator and the census (the cell never reads it). Re-smoked on CPU.
- **PM-4 (tooling): the chain ran `select_ckpt.py` under the REAL python** (the harness ships only the chain), which silently fell back in every sandbox run — and would have masked a broken tool on the node behind a labeled fallback. Fix: `$PY` like every other tool, so the harness stubs it and the node runs the real one. Harness S5/S6.
- **PM-5 (scenario construction, three):** the NAN-ABORT stub keyed on the stage-B dir name; the post-death-screen scenario never created the grid; a stage-selection tie rule was unregistered. All three now assert the actual behaviour (S3c, S3d, S7); the amputation also REMOVES post-death grids so a non-finite grid can never be screened (S3d).
