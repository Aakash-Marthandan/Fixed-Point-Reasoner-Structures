# The width-192 long run and the width clocks — registration (2026-09-14)

**The PI (2026-09-14):** "We need to understand the dynamics in terms of parameter scale and training step time to formalize their mechanisms better. I also notice that since w384 memorizes but w192 doesn't, there must be an optimum parameter scale that generalizes best without memorizing ... We can also try to train one w192 seed beyond 50k steps to see if there is a better optimal point that doesn't memorize." After the descriptive lens: "Yes let's do it. This is worth looking into for the ARC DEC port. But let's use a 50k subsample for evals to test things rather than the full." The standing directive: delete or change no previous result; science integrity first.

**What we already know** (`tools/lens_width_clocks.py`, ledger §5 2026-09-14 night; descriptive):
- **Three clocks, all ordered by width** across ten existing runs at widths 512 / 384 / 192:
  - The held-out monitor's peak: 12k · 12–28k · 46k.
  - The sustained decline: 16k · 24–44k · none by 50k.
  - The fit on training batches (≥ 50 % solved): 18k · 36–44k · never.
- **At one global learning rate**, the width² channel matrices move faster at larger width (spectral relative update per 2k steps: .07 · .10 · .15), while the width-independent 81-cell token-mixing weights move alike.
- **Two hypotheses:**
  - **The learning-rate clock:** width sets the clock through the effective learning rate.
  - **Two rates:** memorization accelerates with width faster than learning, which predicts an optimum width.
- **Three gaps in that picture:**
  - The width-192 clock is censored at 50k.
  - The width-384/512 curves come from noisy 64- and 512-puzzle monitors.
  - The fit instrument is confounded by decision speed.

This run closes the three gaps. This registration is locked at its commit; `tools/analyze_c5l.py` and `tools/c5l_curves.py` adjudicate byte-untouched from it.

## 3. The decision rules (locked verbatim at the top of `tools/analyze_c5l.py`)

**Instruments:** H = held-out exact count of 10,000; T = train-1k exact count of 1,000; the memorization gap = T/1,000 − H/10,000.

- **INTEGRITY.**
  - **I1:** argv equals the champion C5's except out, steps and remat.
  - **I2:** the monitor rows ≤ 50k are identical; the rows 52k–150k are complete; the resume at 50000.
  - **I3:** the 46k and 50k grids are sha256-identical.
  - **I4:** every row's n, split, EMA, depth, grid and run match; the test rows are on the 50k subsample at seed 20260822.
  - **I5:** coverage.
  - **I6:** all test rows on one puzzle set, inside the paper's 46k rows.
- **R-L1 LATER-BETTER.** The 3-grid smoothed held-out curve: the late max (centers 54k–148k) against the early max (12k–48k). ≥ +0.5 pp → LATER-BETTER; ≤ −0.5 pp → EARLIER-BEST; else SAME-PLATEAU. The smoothing guards against picking the luckiest of 50 grids.
- **R-L2 ONSET-W192.** The first grid after the peak from which H stays ≥ 150 counts (1.5 pp) under its running maximum at every later grid, with ≥ 3 grids to the end.
  - **Bands:** ≤ 64k EARLY · 66–90k LR-CLOCK-BAND · 92–146k LATE-BAND · none NONE-BY-150K. The fit onset (the gap ≥ its peak value + 3 pp, sustained) is reported beside it.
  - **Where the bands come from:** the width-384 champion-recipe onsets on the monitor (32k, 44k; median 38k), scaled by the width ratio (×2 → ≈ 65–90k) or the parameter ratio (×3.5 → ≈ 110–165k).
- **R-L3 CLOCK-SCALING.** The same onset definition on every run, on identical instruments.
  - **ρ192** = onset(C5) / median onset(C1, A5): < 2.65 WIDTH-LR-CLOCK · ≥ 2.65 PARAM-CLOCK. If C5 has no onset, the bound 146k / median ≥ 2.65 → PARAM-CLOCK-OR-SLOWER, else UNREADABLE.
  - **ρ512** = onset(A7) / onset(A8), the same seed and recipe: < 1.60 WIDTH-LR-CLOCK · ≥ 1.60 PARAM-CLOCK.
  - **The thresholds** are the geometric means of the width and parameter ratios.
- **R-L4 WINDOW.** onset / peak per run. TWO-RATES-SUPPORTED if width 512 < the width-384 median < width 192 (C5's bound if it has no onset); else NOT-SUPPORTED.
- **R-L5 GAP-ORDER.** The memorization gap at 50k: width 512 > width-384 median > width 192 → GAP-WIDTH-ORDERED; else NOT-ORDERED.
- **R-L6 TEST-50K.** g_val (the letter of record), g_mon (cross-checked by a selector replay) and the 150k grid, each against the paper's 46k on the same 50k test puzzles at D16 and D64.
  - **Per depth:** p < .01 and Δ > 0 → UP; p < .01 and Δ < 0 → DOWN; else FLAT.
  - **Candidate letter:** both UP → BETTER; both DOWN → WORSE; both FLAT → SAME; else MIXED. At 46k → NO-MOVE.

## 5. What each outcome means (fixed now)

- **The paper.** The width-192 row and the abstract stay as they are whatever this run reads. The clock findings enter the paper only as a labeled mechanism paragraph or appendix, on the PI's decision; otherwise they go to paper 2.
- **The ARC DEC port** (the PI's reason for the run):
  - **PARAM-CLOCK and TWO-RATES-SUPPORTED:** the optimum width depends on how much data backs each rule. ARC gives far fewer examples per task than Sudoku's thousand puzzles, so the DEC-ARC should try narrower cells (width 96–128) on long budgets before width 160.
  - **WIDTH-LR-CLOCK:** the effective learning rate is the lever. Scale the learning rate with width in the DEC-ARC (μP-style) and keep the capacity. The next Sudoku test is width 384 at lr 5e-5 with weight decay 2.0.
  - **LATER-BETTER or NONE-BY-150K:** narrow cells need long budgets. Give the DEC-ARC pretrain at least twice the wide cells' budget, and select on a large held-out set.
  - **EARLIER-BEST with an EARLY onset:** the 50k budget was near the optimum, and the clock picture needs revising before it guides the port.

## 7. What could fool us, and the guard on each

- **One seed for the long run, and four single wide runs.**
  - **Guard:** the clock readings are descriptive in strength and labeled so. The pairs are chosen within one recipe (ρ192: the champion recipe; ρ512: the plain recipe, seed 1).
- **A noisy onset.**
  - **Guard:** the 10k held-out set resolves ≈ 0.2 pp per grid, and the onset needs a sustained 1.5 pp drop over ≥ 3 grids. C7's 38k dip (−2.4 pp, recovered by 40k) would not fire.
- **The bands in R-L2 come from monitor-based width-384 onsets.**
  - **Guard:** R-L3 recomputes the ratios on identical instruments.
- **The per-row batch state resets at the resume.**
  - **Guard:** it did so in every registered extension (C5, C7, C8); part of the extension path.
- **The train-1k instrument reads the canonical training puzzles**, which the trainer saw under position augmentation.
  - **Guard:** the gap reads memorization of puzzle content, the quantity that matters.
- **Picking the luckiest of 50 late grids.**
  - **Guard:** R-L1 compares smoothed maxima; R-L6 tests the candidates on independent test puzzles.
- **The analysis overwrites local data.**
  - **Guard:** pulls land in a new directory.
